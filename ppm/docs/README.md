# The PPM's knowledge base

How the PPM was made, and how to keep working on it at the same quality, whoever does the work: a teammate, or an AI session starting with no memory of earlier work. Read it before changing anything sizeable.

## Read in this order

1. [index.md](index.md): every page, and what it's for.
2. The repository's [`docs/how-we-work.md`](../../docs/how-we-work.md): the mindset.
3. The guides your task needs: [design system](guides/design-system.md), [UX principles](guides/ux-principles.md), [architecture](guides/architecture.md), [database](guides/database.md), [testing](guides/testing.md), [workflow](guides/workflow.md), [limitations](guides/limitations.md).
4. [backlog.md](backlog.md), and the last few entries of [log.md](log.md).

## How it's organised

It follows the repository's conventions ([`docs/README.md`](../../docs/README.md)): `index.md` and `log.md`; `guides/`; `decisions/`; `people/`; `for-humans/` (things only a person can do); `references/`; `raw/` (what people gave us, kept as given); `reports/` (for large pieces of work only).

## Rules

- **It's public.** No keys, passwords, database dumps, client data, personal details or private notes.
- **Write like a teammate showing someone around:** warm, plain, short sentences, terms explained, dates as 2026-10-06, no em dashes.
- **Keep it true:** change the page in the same commit as the code it describes, and date what you check.
